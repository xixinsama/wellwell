# 绘制水域房间（地图与初始水体）

这份指南写给"自己画房间"的人：怎么铺地形、怎么放 `WaterBasin`/`WaterGate`、初始水怎么填、落差水柱怎么自动贴边，以及怎么让三池级联真正流起来。示例数值都来自 `water_cascade`（`tools/build_water_cascade.gd` 生成），可以直接对照。

## 1. 模型速览（先理解这三件事）

- 水是**一维高度场**：每 8px 一列，一列只有一个"水面高度"和一个"地面高度"。
- **地面来自地形**：从房间底部往上找，连续实心的那一摞的顶面就是这一列的地面。所以"池底"必须是**一直实心到底部**的一摞砖，不能悬空。
- **模拟范围来自水盆标记**：`WaterField` 只模拟所有 `WaterBasin` 矩形的并集。没有水盆标记的池子根本不会参与模拟。

## 2. 画地形

规则只有一条：**每一层水面下面都要有实心砖撑到房间底部**。

- 高池（A）：`cols 2..12`，从 `row 7` 一直实心到底（`row 22`）。水面在 `row 2`。
- 堰口（A→B）：`col 13`，从 `row 5` 实心到底。它比 A 的池底高 2 格，所以 A 的水必须先涨到 `row 5` 才能漫过去；水柱会自动画在它右侧。
- 中池（B）：`cols 14..25`，`row 12` 实心到底。
- 堰口（B→C）：`col 26`，`row 11` 实心到底（只比 B 的池底高 1 格，这样 B 很快就能漫过去）。
- 低池（C）：`cols 27..38`，`row 19` 实心到底。

注意：

- 池底下面**不要留空气**（比如在 `row 7` 铺一层砖、下面空着）。扫描会一直走到房间底部，悬空的一层砖不会成为"池底"。
- 所有 x 尽量落在 8px 网格上（`col * 8`），否则列会错半格。
- 水面不要贴到房间最上面一行（`row 0` 是边界墙）。

## 3. 初始水体：`WaterBasin`

一个 `WaterBasin` 标记 = 一块初始水：

| 属性 | 含义 |
| :--- | :--- |
| `position` | 水池**左上角**的格子（`col * 8, row * 8`） |
| `size_cells.x` | 水池宽度（格） |
| `size_cells.y` | 初始水深（格，向下数） |
| `surface_offset` | 水面再往下偏移多少 px（可选） |
| `basin_id` | 调试名 |

它的**上边缘就是初始水面**，水会从那里一直填到地形池底：

```
A: position = (2*8, 2*8)   size = (11, 5)   # 11 格宽，水面 row 2，池底 row 7 → 深 40px
B: position = (14*8, 12*8) size = (12, 1)   # 顶部贴在池底 → 初始为空，只用来撑开模拟范围
C: position = (27*8, 19*8) size = (12, 1)   # 同上，空的
```

**空的池子也要放一个贴底的标记**（高度填 1），否则它不在模拟范围里，上池的水落下来也不会有水面。

## 4. 落差水柱的自动规则

`WaterField` 每帧找出所有"相邻两列水面差超过 `waterfall_min_drop`（默认 5px）"的地方，最多同时画 4 根水柱：

- **贴边**：向右流（左侧高）时，水柱的左边缘正好贴着低处水池的左边缘；向左流（右侧高）时，右边缘贴着低处水池的右边缘。
- **加宽**：流量越大（用该列的通量速度估算），水柱越宽，**朝背离堰口的方向**加宽；最宽 3 格（24px）。
- **不越界**：只会占用开放格子，撞到实心砖就停，所以永远不会画到碰撞体上。
- **高度**：就是上下两个水面的真实落差。

所以画地图时不用手动放瀑布，只需要把"堰口"（高池底 + 实心底）和"低池"画对，水柱会自己贴到正确的一侧。

## 5. 让级联真正流起来（水量计算）

一个容易踩的坑：上池漫过一次之后，会**留下和堰口等高的一层水**，剩下的才流走。所以：

```
上池存水量   = 宽(格) × 8 × 深(px)
残留在上池的 = 宽(格) × 8 × (堰口高度 - 上池底高度)
能流出去的   = 上池存水量 - 残留
下池要装满到它的堰口 = 下池宽(格) × 8 × (下池底到堰口的高度)
```

`water_cascade` 的数值：

- A：11 格宽、深 40px → 3520 px²；堰口比池底高 16px → 残留 1408；**可流出 2112**。
- B 要涨到自己的堰口需要 12 × 8 × 8 = 768 → 2112 - 768 = 1344 会继续流向 C ✓。
- 如果 B 的堰口太高（比如比池底高 24px，需要 2304），A 的水就不够，B 永远到不了堰口，C 会一直干着。

想让水**持续流动**而不是流干，再加一个水源：上池左侧再放一个更高的 `WaterBasin`（或打开一个 `WaterGate` 的储水），或者周期性调用 `WaterField.request_splash()` 补水。

## 6. 编辑器里的操作顺序

1. 打开 `scenes/levels/test/water_cascade.tscn`（或复制一个模板房间），在 `RoomContent/Terrain/SolidTiles` 里按上面规则铺砖。
2. 在 `RoomContent/Entities` 下放 `WaterBasin`（每池一个，空池贴底放高度 1）。
3. 需要闸门就放 `WaterGate`（它会把覆盖的列临时当成墙，`open_delay_seconds` 后放开）。
4. 房间必须有覆盖全房的 `FogZone(Light)`；如果用气体，再放 1–2 个 `FogLight`。
5. 保存源场景，运行生成器重新烘焙：
   ```powershell
   godot --headless --path . -s res://tools/build_water_cascade.gd
   ```
6. 运行 `addons/fluid_kit/demos/water_demo.tscn`（气体已关）看效果。

## 7. 常见问题

| 现象 | 原因 |
| :--- | :--- |
| 水没有出现在某个池子 | 那个池子没有 `WaterBasin` 标记（模拟范围只覆盖标记的并集） |
| 池底不对/水填到房间底部 | 池底那摞砖没有一直实心到底，或者中间有空气 |
| 水一直漫不过去 | 上池的水量不足以让水面升到堰口高度（按第 5 节算一下） |
| 水柱画到了砖上 | 堰口的"低处一侧"其实是实心砖：检查堰口列右侧/左侧第一列是否有开放格 |
| 水面高度差半格 | 地形没有对齐 8px 网格 |
| 级联停下来 | 正常：上池已经降到堰口高度，没有水源补充 |

## 8. 两池变三池的最短步骤

在现有两池房间上加高池：

1. 在 `SolidTiles` 里给新池铺一摞到底的砖（例如 `cols 27..38`、`row 19`）。
2. 在它左边放一个堰口列（比新池底高一格），实心到底。
3. 给新池放一个贴底的 `WaterBasin`（`size = (宽, 1)`），保证模拟范围覆盖它。
4. 如果希望它把水**送给**左边的池子（向左流），把左边池子的堰口画成"左边低、右边高"，水柱会自动贴左侧低池的右边缘。
5. 重新烘焙 + 跑 `water_demo`，按第 5 节把水量调够。

# 二：2D 栅格流体（`WaterGrid` + `FluidRegion`）

上面那套是**一维水柱**：每个 x 只有一个水面，适合池塘、级联、瀑布。如果你想要 Noita 那种"每个格子都有水、水会在墙与墙之间流动、会从洞里漏下去"的效果，用这一套。

只需要摆两种东西：

1. **一堵墙** —— 就是普通的 `SolidTiles` 瓦片（和画地形完全一样）。
2. **一块流体** —— 放一个 `FluidRegion`（`RoomContent/Entities` 下），矩形区域就是初始水体的体积。

没有别的标记，也不用画水面线：运行时 `WaterGrid` 会自动接管，整间房按 8px 一格模拟。

## 1. 规则

- `FluidRegion` 的矩形**被水填满**：区域内每个空格子初始都是满的。
- 区域里的瓦片墙**不占水**：那块体积直接被扣掉（"保留墙之外的体积"）。
- 水会自己往下掉、往低处摊平、从边缘漫出去；**不会向上流**，所以不会爬上墙。
- 水位高过堰口就会漫过去，形成瀑布；地面有洞就漏下去。
- 体积严格守恒：水只是从一格搬到另一格，不会凭空消失或产生。

## 2. 房间示例（`water_grid`）

`scenes/levels/test/water_grid.tscn`（生成器 `tools/build_water_grid.gd`，**手改过瓦片就不要重跑它**）：

```
左侧水池：cols 1..18 一直实心到 row 22，池底 row 14
堰口/dam：col 19，从 row 9 实心到底
右侧地面：cols 20..38，地面 row 19
排水洞：  cols 30..31，rows 19..21 空着（掉到 row 22 的坑里）
岩石柱：  cols 8..9，rows 8..13 —— 故意立在流体区域里
FluidRegion：position (2*8, 5*8)，size (17, 9)
```

岩石柱就是"墙在流体里"的例子：区域表面积是 17×9，实际体积少了 2×6 格。

## 3. 参数（`WaterGrid` 节点）

| 参数 | 默认 | 作用 |
| :--- | :--- | :--- |
| `cell_pixels` | 8 | 模拟格子大小。8 和瓦片对齐、最省；4 更细腻但格子数 ×4 |
| `sim_hz` | 60 | 模拟频率 |
| `lateral_rate` / `fall_rate` | 24 / 1 | 横向摊平速度 / 每步下落速度 |
| `splash_depth` | 1.6 | 角色入水时推开的深度 |
| `shallow_color` / `deep_color` | 见节点 | 浅水/深水颜色 |

放在 `scenes/runtime/world_root.tscn` 的 `WaterGrid` 节点上；房间里没有 `FluidRegion` 时它完全不启动。

## 4. 和玩家/代码交互

`WaterGrid` 实现了和 `WaterField` 相同的查询，玩家游泳组件不用改：

```gdscript
water_grid.is_ready()
water_grid.get_surface_y_at_point(player.global_position)   # 优先用这个（2D 精确）
water_grid.get_surface_y_at(x)                             # 兼容旧接口
water_grid.get_flow_velocity_at_point(point)
water_grid.add_water(point, radius, volume)                # 加水（水源）
water_grid.remove_water(point, radius, volume)             # 抽水
water_grid.request_splash(x, impact_speed)                 # 入水水花
```

## 5. 注意事项

- 一片很宽的水池要**摊平需要几秒**：模型是守恒的格子流，不是无粘流体。
- 房间太大（多个 chunk）时把 `cell_pixels` 调成 8 或 16，格子数按面积平方增长。
- 静止后模拟会自己睡眠，`step` 不再花时间；只有水在动时才占用 CPU。
- 全部房间跑满水的最坏情况约 0.8ms / 步（320×180、8px 格）；普通水池只占其中一小块。
- 入水/跳跃的水花是**纯视觉**的：粒子 + 着色器里的一圈表面波纹（`ripple_amplitude`）。它不会排开水面、也不会增加体积，所以跳进跳出水面完全不花模拟时间。
