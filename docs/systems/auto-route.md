# 自动路线（Auto Route）

正式游戏里按 `F4` 打开自动路线工具：在光标处设起点 A 与终点 B，自动规划一条
用**跳跃、八方向冲刺、冲刺跳、跳冲、贴墙攀爬、登墙跳与楼梯**的路线，然后由角色
自己跑过去。

## 操作

| 键 | 作用 |
| --- | --- |
| `F4` | 打开 / 关闭工具（关闭即恢复手操） |
| 方向键 / `WASD` | 移动 8 px 光标；按住 `Shift` 一次移动 4 格 |
| `空格` | 把光标位置设为起点 A（绿） |
| `X` | 把光标位置设为终点 B（品红） |
| `Enter` / `Z` | 规划并出发 |
| `Backspace` | 清空 A / B 与路线 |
| `Esc` | 关闭工具 |

打开工具时角色输入被屏蔽，方向键只移动光标。按 `Enter` 出发时角色被放回 A 点，
随后按路线逐帧执行；路线按动作着色画在地形上（走=白、跳=青、冲刺=品红、攀爬=橙、
爬梯=绿）。

## 求解方式

| 层 | 做什么 |
| --- | --- |
| `AutopilotGrid` | 从当前房间的真实物理空间栅格化：4 px 碰撞掩膜 + 8 px 落脚/梯子格。**单向平台按瓦片的 `one_way` 碰撞多边形判定**（`TileData.is_collision_polygon_one_way`），单独一层：向下拦住、向上和横向穿过——就是瓦片里那几块 (0,4)~(3,4) 平台。房间边缘外再多取 2 格，边界墙按真实几何判断 |
| `AutopilotMotion` | 把一段动作（跳、冲刺、冲刺跳、跳冲、爬梯、攀墙、登墙跳）按真实的 `MovementProfile` 与 Dash 资源逐帧模拟成轨迹与输入脚本；只生成角色**真的拥有**的能力（冲刺/攀爬未解锁时不会规划） |
| `AutopilotPlanner` | 在（格子，状态）上跑 A\*，代价是帧数；节点是可落脚点、梯子格、贴墙格和空中的决策点；终点判定同时看格子和身体位置。地面起点的模拟腿按（节点 + 动作 + 速度）缓存复用，重规划时直接命中 |
| `AutopilotDriver` | 通过角色的输入源接口逐帧重放。冲刺那一下会把方向写进左右/上下轴（手柄与键盘都是这么读的），否则斜冲会变成横向冲；每段结束若位置或速度与计划不符、或跑动中偏航超过 10 px，就上报给上层 |

**只在打开工具时扫描一次**：进房间、出房间都不重建栅格，换房间会直接关掉工具并丢弃栅格，等你自己再按 `F4` 重新扫描。扫描本身**按帧分片**并被画成一个从房间顶部向下推进的扫描带：落脚点随着扫过逐行亮起（单向平台用另一种颜色），所以既没有单帧卡顿，效果也对应真实进度。

**规划在后台线程跑**：`WorkerThreadPool` 上执行 A\*，主线程每帧只查一次任务是否完成，所以规划时游戏照常跑、照常渲染，不再卡住画面。实测（`the_world` 的 40×23 房间）：首次规划约 0.1 秒（简单路线）到 2 秒（多层塔楼），**缓存的重复规划约 2 毫秒**。

执行端的兜底：偏航后不会原地硬演，而是先落稳（地面/梯子/贴墙），从那里重新规划；同一轮里连续两次没有进展就停下并显示 `STUCK`。到达判定要求角色**站在**终点附近（6 px 内），从终点上方飞过不算到达。

## 松弛（单向）

规划用的是逐帧精确模拟，但控制器给玩家的宽容比"精确"多，所以求解器可以**单向**松弛：只在
"实机比模拟更有余量"的方向留出余量，回放误差自然被吃掉。反方向（模拟乐观）会规划出实机做
不到的动作，只会变成重规划循环；也不要随机化，同一起终点出不同路线会让问题不可复现。

| 宽容来源 | 数值 | 怎么用 |
| --- | --- | --- |
| 长按跳 | 变量跳窗口 0.2 s | 执行端比计划多按住 4 帧，实机弧线只会更高（被 0.2 s 硬截断，不会超出角色能力）|
| 拐角修正 | 跳：横向 4 px + 上 1 px；横向冲：上下 4 px | 模拟里允许擦角通过，不把能做到的路线判死 |
| 土狼时间 / 跳跃缓冲 | 0.1 s / 0.08 s | 起跳可以偏一两帧仍然生效 |
| 冲刺攻击窗口 | 0.3 s | 冲→跳、跳→冲 的衔接不需要精确到帧 |
| 抓墙吸附 | 4 px | 墙在吸附半径内就算可抓 |
| 单向平台 | 瓦片 `one_way` | 从下往上穿（已建模）|
| 到达 | 6 px / ±1 格 | 站在终点附近即算到达 |

执行端的判定也按同一方向放宽，否则"比计划更好"会被当成偏航去重规划：

- 跳跃弧线**比计划更高**不算偏航（多按的那几帧只会加高度）；跳跃段会等落地再进下一段。
- 梯子段的起点高度是整格量化，实机悬停在抓点，所以梯子段不比对高度/入段速度。
- 地面节点不再生成 `fall` 段：那是"按住方向盲走 220 帧"，比逐格走便宜，会让 A\* 选它，然后现实里撞上一格高的台阶卡死。只有真正走下平台边缘（相邻格不是落脚点）才生成下落段。
- 逐格走的 `walk` 段会做碰撞检查，撞到薄唇边就丢弃，交给跳跃段解决。

已知还能继续松、但还没做的：贴墙爬按 85% 体力预留；连招延迟窗口化；抓墙探测距离对齐 4 px
吸附半径；A\* 给"离墙远、落点居中"的腿打折（同代价下优先更稳的路线）。

**落点余量（已实现，默认关闭）**：`AutopilotPlanner.stability_bias` 按落点周围空余格数给腿加排序
权重，只进优先级、不进 `g`，并且有上限。16 房基准上它把一条 19 段、平均余量 0.63 的"贴天花
板钻隧道"路线换成 5 段、平均余量 3.00 的"从屋顶走"路线，多花约 50 帧；但在最深的一条路线上
会破坏可达性，所以默认 `0.0`，详见 [benchmark.md](../benchmark.md)。

## 共享模拟器的占用锁

栅格、模拟器和规划器是**同一份实例**：工具的后台线程在规划，编辑器探针/playtest 也可能
伸手去调 `simulate()`。`AutopilotGrid.move_box()` 把结果写在栅格的 `last_move_*` 字段上，
两个所有者同时模拟会互相覆盖，产出"走一格跳到半空"这种假数据。

所以加了一把按所有者计数的锁（`autopilot/autopilot_lock.gd`）：

- 规划器整段搜索持锁（owner `planner`），扫描每帧持锁（owner `scan`），外部探测默认 owner
  `external`；
- 同一 owner 可重入，所以规划器在自己的锁里调用模拟器不会被自己挡住；
- 拿不到锁时 `simulate()` 返回 `null`、`plan()` 返回空路线，并在日志里留一条 warning，
  而不是给出脏结果；
- 工具对外提供 `get_lock_state()` 和 `try_simulate(start_state, action)`：探针先问状态，
  忙时直接拿到 `{"ok": false, "busy": ...}`，空闲时由工具代持锁跑一段并返回终点格/帧数。


- 只求解**当前房间**。目标在房间外或跨房间，直接显示 `NO ROUTE`。
- 不模拟水面、移动平台、可破坏地块和机关；这些位置可能被判为不可达，或执行中触发重新规划。
- 贴墙攀爬按体力上限裁剪：连续向上最多 12 格。
- 单向平台只按“从下往上穿过”的语义建模（瓦片里那种地面平台）：向下拦住、可站立，向上和横向穿过。旋转/翻转到墙面的单向瓦片不单独建模。
- 模拟按 4 px 栅格判定碰撞，实机瓦片碰撞比栅格大零点几像素：贴着墙角飞过的计划段，实机可能被弹回，然后触发一次落地重规划。模拟身体因此比实机高 1.2 px 留出余量，但仍不是逐像素一致。
- 首次规划仍是 0.1–2 秒的**后台**计算（画面不卡，但路线出现有延迟）；重规划命中腿缓存后通常 2 ms 内完成。
- 换房间会关闭工具并丢弃栅格，需要重新按 `F4` 扫描；扫描约 0.3 秒（按帧分片，每帧约 2 ms）。
- 覆盖层文字用 ASCII：引擎默认字体没有中文字形，写中文会变方框。
