## 需要完成的东西

### 开始菜单界面

提供一个简易的，且易于修改的开始界面，包含：

- 开始游戏
- 设置
- 退出游戏

开始游戏可以选择游戏栏位
游戏栏位分为空栏位和有存档的栏位
有存档的栏位可复制和删除到其他栏位

设置包含基础画面设置和音量设置

### 空关卡与关卡总编辑器

一个房间就是一个关卡，玩家进入房间后，场景内应该包含房间里的所有东西

区块是最小的加载单元

一个房间由多个区块组成，不限制区块之间如何摆放，但最好是连接在一起的，且区块组成矩形房间，如2*2

空关卡是一个场景，继承空关卡新建的场景可以自由编辑，编辑后可直接游玩体验
因此，空关卡内包含：

1. 场景根节点，控制单个关卡游玩
2. tilemaplayer 地形层，作为总编辑器的依据
3. player 玩家操控角色
4. 摄像机

其他内容由创作者任意填充，包括前景后景，实体，敌怪，甚至流体层
保存继承的关卡场景后，会进行烘焙，导出一个实际加载场景，该场景包含：

1. 关卡基本信息，比如区块大小等
2. tilemaplayer 地形层实际数据（只有数据）
3. 挂载的 Node2D 根节点
4. 创作者其他内容直接挂载在根节点上

所以创作者需要在继承的关卡场景自行编排内容的渲染层次和渲染顺序，当进入游戏主场景时，会依次发生如下

1. 先加载主场景框架，包含游戏管理器，一个地形层 tilemaplayer
2. 获取数据，赋值主场景，地形全加载（因为实际占用和性能要求不高），准备后续加载实际场景
3. 获取到角色出生位置，加载对应关卡（实例化烘焙的实际加载场景），加载关卡周围关卡（根据玩家所在区块来判断，如果玩家周围四个区块都是其他房间，则加载对应其他房间的内容，否则不加载），为的是在1帧内切换房间
4. 摄像机准备好，结束从菜单的转场动画

游戏主场景运行时，根据角色位置后台加载周围房间，不要让玩家进入房间察觉到明显卡顿

关卡总编辑器，这是专门为编辑所有关卡做的godot内插件工具，对已烘焙的关卡进行：

- 增：增加进入游戏主场景，运行游戏主场景后只有增加的关卡才会出现；新增的场景出现在左上角的负左边内
- 删：删除关卡，将对应关卡从游戏主场景中删除
- 改：编辑移动关卡之间的位置；允许区块之间覆盖，

### 基本元素详细设计

tilemaplayer 地形层详细设计：

单向平台：有些游戏可以让角色按住下方向键和跳跃键来通过单向平台，这个作为设置的一部分

存档点与出生点：出生点作为游戏一开始角色出生的地方，可以与存档点不处于一个位置，出生点可以使用Mark2D节点直接放置在游戏主场景内，或是直接记录在代码中；存档点有分接触即存档和需要按交互键存档两种，而接触存档为了避免角色来回移动反复触发，要求离开房间后重新回到存档点才能触发

镜头移动的抖动效果，选择开启或关闭

角色操控的基本现代化处理：狼跳，下落时提前按跳跃的输入缓冲，顶头偏移
