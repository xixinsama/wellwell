## 需要完成的东西

### 开始菜单界面

提供一个简易的，且易于修改的开始界面，包含：

- 开始游戏
- 设置
- 退出游戏

开始游戏可以选择游戏栏位
游戏栏位分为空栏位和有存档的栏位
有存档的栏位可复制和删除到其他栏位

设置包含基础画面设置和音量设置

### 空关卡与关卡总编辑器

一个房间就是一个关卡，玩家进入房间后，场景内应该包含房间里的所有东西

区块是最小的加载单元

一个房间由多个区块组成，不限制区块之间如何摆放，但最好是连接在一起的，且区块组成矩形房间，如2*2

空关卡是一个场景，继承空关卡新建的场景可以自由编辑，编辑后可直接游玩体验
因此，空关卡内包含：

1. 场景根节点，控制单个关卡游玩
2. tilemaplayer 地形层，作为总编辑器的依据
3. player 玩家操控角色
4. 摄像机

其他内容由创作者任意填充，包括前景后景，实体，敌怪，甚至流体层
保存继承的关卡场景后，会进行烘焙，导出一个实际加载场景，该场景包含：

1. 关卡基本信息，比如区块大小等
2. tilemaplayer 地形层实际数据（只有数据）
3. 挂载的 Node2D 根节点
4. 创作者其他内容直接挂载在根节点上

所以创作者需要在继承的关卡场景自行编排内容的渲染层次和渲染顺序，当进入游戏主场景时，会依次发生如下

1. 先加载主场景框架，包含游戏管理器，一个地形层 tilemaplayer
2. 获取数据，赋值主场景，地形全加载（因为实际占用和性能要求不高），准备后续加载实际场景
3. 获取到角色出生位置，加载对应关卡（实例化烘焙的实际加载场景），加载关卡周围关卡（根据玩家所在区块来判断，如果玩家周围四个区块都是其他房间，则加载对应其他房间的内容，否则不加载），为的是在1帧内切换房间
4. 摄像机准备好，结束从菜单的转场动画

游戏主场景运行时，根据角色位置后台加载周围房间，不要让玩家进入房间察觉到明显卡顿

关卡总编辑器，这是专门为编辑所有关卡做的godot内插件工具，对已烘焙的关卡进行：

- 增：增加进入游戏主场景，运行游戏主场景后只有增加的关卡才会出现；新增的场景出现在左上角的负左边内
- 删：删除关卡，将对应关卡从游戏主场景中删除
- 改：编辑移动关卡之间的位置；允许区块之间覆盖，

### 基本元素详细设计

tilemaplayer 地形层详细设计：

单向平台：有些游戏可以让角色按住下方向键和跳跃键来通过单向平台，这个作为设置的一部分

存档点与出生点：出生点作为游戏一开始角色出生的地方，可以与存档点不处于一个位置，出生点可以使用Mark2D节点直接放置在游戏主场景内，或是直接记录在代码中；存档点有分接触即存档和需要按交互键存档两种，而接触存档为了避免角色来回移动反复触发，要求离开房间后重新回到存档点才能触发

镜头移动的抖动效果，选择开启或关闭

角色操控的基本现代化处理：狼跳，下落时提前按跳跃的输入缓冲，顶头偏移

这两项都是**气体渲染**的延伸，已经想清楚钩子和代价，但会改变整屋观感，所以先记录在这里，
不动代码。技术细节写在 `addons/fluid_kit/README.md` 的 "Recorded, not implemented" 一节。

### 气体给地面/墙投影

现状：气体只**读**光照图（`Atmosphere.set_light_field`），从不写回；光照图内容只有黑底 +
提灯三层加色 PointLight2D + 房间灯 + 瓦片遮挡体。全仓库只有 `fog_layer.gdshader` 采样
`gas_texture`（雾自身密度、细节 tracer、体积自遮挡的 6 次取样），所以气体目前**不会**给场景
投影。已有的自遮挡只是雾内部"离灯远的一侧更暗"。

两种实现档位，钩子都在 `LightField`：光照视口是房间尺寸且 `UPDATE_ALWAYS`，在它的画布根里
加一张全房间 quad，采样气体密度：

1. **吸收式（无方向）**：`light *= exp(-density * k)`，每像素 1 次采样。320×180 房间
   5.76 万像素、2×2 房间 23 万像素，60 Hz 下分别约 3.5M / 13.8M 次/秒 —— 相对实测
   2×2 房间整帧 1.29 ms（其中光照图已是大头）可忽略。
2. **方向性投影**：趴在光照图里朝提灯做和体积自遮挡一样的 6 次步进，`light *= exp(-Σρ)`
   → 烟在灯的相反方向把地面压暗，读起来像真的投影。6 倍采样，仍可忽略。

必须注意的三点：(a) 雾自己也读这张图算 `lit`（`map_weight 0.5`），浓烟会**被算两次暗**
（自遮挡 + 经光照图），所以要么加权、要么二者留一；(b) 需要 `max_darkness` 式封顶，
否则有烟的地方整屋发闷（参考 `BackdropShadow` 的做法）；(c) 默认值应偏向轻，并配一个
开关，用 `gas_diagnostic.gd` 的冻结同帧 A/B 量完再定。

### 光照透过气体造成丁达尔效应（光柱）

关键点：现有的体积步进已经在算 `T = exp(-Σρ)`，那是**吸收**项；同一个循环里
`1 - T` 就是**朝观察者散射**的那部分 —— 也就是 2D 侧视图里的丁达尔光柱。所以第一版的
数学是现成的，差别在合成方式：

- 它必须是**加色**的（往画面加光），不能像自遮挡那样乘在雾的颜色上；而雾层的 `COLOR`
  在 blend 时会被 alpha 乘，所以光柱应该做成独立的一层（放在 `LightGlow` 所在的 z 9，
  加色），或者在光照/泛光链路里做，而不是塞进 `fog_layer`。
- 需要**朝向每盏灯的方向**（目前只给主光源的世界坐标）、需要被墙遮挡（要么用光照图的
  阴影项，要么把遮挡体多边形也纳入步进），否则墙后的烟也会发光。
- 需要封顶/色调映射，并且要和雾层的蓝噪声阈值配合，别让加色光和抖动颗粒互相打架。

建议的落地形态：独立的 `light_shaft` 加色 pass（z 9，紧邻 `LightGlow`），共享气体纹理与
光照图，导出 `shaft_strength / shaft_length / shaft_steps / shaft_max_add`，先默认关，
量完亮度和帧成本再决定默认值。
